# M6 outputs: curtains and output drop-outs (2026-11-17)

Machine: the owner's dev laptop (GTX 1070, one 4500×3000 internal display,
60 Hz), outputs as windows. ENGINE M6 branch `claude/engine-m6-outputs`.
Other agents (MEDIA ingest) were working on the machine at the same time.

## 1. Kill the renderer → black → back

Method: `himmel.exe --no-controller --no-weapons --no-ui --no-audio --
--outputs 3 --size 640x360 --no-show-files`, clip 0 on A1, then
`python src/engine/tools/curtain_check.py --runs 6 --gap 6`. Each run:
1. sample 5 points per output from a BitBlt of the desktop;
2. `taskkill /F` the renderer;
3. sample every 20 ms until every output is black, then until it shows the
   show again.

| Run | Black after | Show back after |
|---|---|---|
| 1 | 0 ms | 1043–1078 ms |
| 2 | 0 ms | 1544–1601 ms |
| 3 | 0 ms | 1212–1250 ms |
| 4 | 0 ms | 1341 ms |
| 5 | 0 ms | 1237–1272 ms |
| 6 | 0 ms | 1240–1278 ms |

- No sample ever showed the desktop. The renderer logs its start-up as
  595–906 ms from process start to the first frame.
- What happens on a kill: the supervisor sees the exit within 50 ms, waits
  0.25–0.5 s of back-off, and the renderer starts in ~0.7 s. The rest of the
  time is the restored clip decoding its first frame.
- Before the fixes: the DWM close animation faded the old picture over the
  curtain for ~150 ms (now off), and the restart back-off grew to 4 s in a
  kill loop (now capped at 0.5 s for the renderer).

## 2. Pull an output cable (simulated) → the others never stutter

Method: the same stack with 3 clips on air. First 2 min with nothing
happening (baseline), then 60 cycles of `himmel_cmd simlost 2 on` (1 s) /
`off` (1 s). That hides and shows OUT 2's window and takes it out of the
wait set and back in, which is the same code path as a real display loss in
windowed mode. Measured with the renderer's 5 s STATS lines.

| | Late frames | Interval max | CPU per frame max |
|---|---|---|---|
| Baseline, 2 min | 0 | 17.25 ms | 1.6–7.4 ms |
| 60 pulls, ~2.3 min | 1 (one 33.4 ms frame, at the start of the pulls) | 17.16 ms (33.4 once) | 5.0–9.5 ms |

- Every return was measured, the last one 1116 ms (the time the script
  waited).
- A hide / show costs a few ms of CPU on the render thread (`ShowWindow`),
  well inside the 16.7 ms frame.
- The single late frame could be the first hide or the machine. It was not
  repeated in the other 59 cycles.
- Not measured here: a real cable pull and a full-screen output on a second
  display (the laptop has one screen). The full-screen path was checked once
  on the laptop panel with `simlost`: OK → LOST → OK, back in 925 ms. The
  owner should repeat this with real projectors (M12 soak).
