Himmel: the 8 grid columns are 8 layers (one playing clip lit per column), the mute LEDs show live layers, XL / XR show the crossfader side, BPM blinks on the beat (tap it). Follow: a LED lights while you hold its button. Text: a scroller on the grid. All 75 LEDs go out as one Ohm64 SysEx (F0 00 01 61 02 04 …, from the user guide); the drawing shows what the device shows.

Real Ohm64: probe, map and LEDs

Plug the Ohm64 in with USB and close the Livid Editor (Windows lets one program use a MIDI port). Press Use the real Ohm64. Himmel then only listens. It never saves settings, never resets and never remaps the device: the hardware link has an allow-list (LED SysEx, requests, notes, dimmer CCs, Local Control).

1 · Read the map from the Ohm64 (asks only, changes nothing)

The Ohm64 can tell what every button and analog input sends (requests 07.0B and 07.0A), its MIDI channel and its settings. The answer becomes the starting map; on the simulator it shows the simulator's own guess.

2 · Touch every control

The drawing follows the real Ohm64. A green dot = seen on the hardware. A dashed red outline = not in the map. Wrong control moves? Click the right one in the drawing, then move the real one. The map is saved to ohm64_map.json (backup .bak.json). Esc cancels.

3 · LEDs

Let Himmel drive the LEDs first asks what the device shows and whether Local Control is on, then turns Local Control off (not stored) so only Himmel lights them. Give them back restores both. Then try All on, Chase and Follow. LED hunt lights one LED code at a time (column 1-6, row 1-14): click the button that lit and its code is saved (from the guide's tables we know where they should be; the mute order differs between two of its tables). Nothing lit? Step on.
